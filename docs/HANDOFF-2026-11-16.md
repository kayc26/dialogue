## Watch for

- **Deploying the function**:
  - run `npx -y neon@latest config plan --branch <branch> --env .env.local` first;
  - then `npx -y neon@latest deploy --branch <branch> --env .env.local --no-env-pull`;
  - without `--no-env-pull`, the CLI rewrites `.env.local`'s `DATABASE_URL` to that branch, and `kb:load` would then load the wrong branch;
  - after a deploy, the old copy can keep answering for about a minute.
- **Testing the function**: curl skips the browser's CORS preflight. Test with `-X OPTIONS -H "Access-Control-Request-Method: POST" -H "Access-Control-Request-Headers: authorization,content-type,x-title"`.
- **Production changes** (database, deploys, `kb:load`, pushes) change what testers see. Get Kay's explicit OK. This session's permission rules block some of them until then.
- **`.env.local`** holds the shared OpenRouter key and the owner database URL. Never print or inspect it; scripts read it via `--env-file`.
- **Spending**: the $15 OpenRouter budget (ADR-0012). Ask Kay before any live run (`kb:eval-faq --yes` costs about $0.01).
- **Reading test runs**: read `kb/out/eval-faq.md` by whole sections. Answers span several paragraphs, and line-matching (grep) shows only the first; earlier scores were wrong because of this (ADR-0013, iteration 20).
- **ADR tools** treat only `answered` as closed: `moot`, `superseded`, and `deferred` still show as open.
- **`kb:load`** replaces every passage and re-syncs card approvals in the same transaction.
